# 模拟投资实验使用与维护指南

本版本支持一个人民币模拟账户：人工记录每日决策，CSV 导入交易日历和收盘行情，按下一交易日收盘价模拟成交。账户累计收益、沪深 300 对比和最大回撤来自同一套账本。数据保存于 PostgreSQL，浏览器不保存权威账户数据。

## 启用

1. 安装 Node.js 22 或更新版本，运行 `npm ci` 和 `npx prisma generate`。
2. 准备 PostgreSQL，在服务端配置 `DATABASE_URL` 与 `DIRECT_URL`。本地可使用被 Git 忽略的 `.env`；不要把真实连接信息提交或写入文档。
3. 按下面的迁移分支完成数据库升级。构建命令不再自动执行 `db push` 或修改生产结构。
4. 在自己的终端运行 `npm run paper:credentials`。保存终端显示一次的随机登录口令；将输出的 `PAPER_PASSWORD_HASH`、`PAPER_SESSION_SECRET`、`CRON_SECRET` 设置为服务端环境变量，不要加 `NEXT_PUBLIC_` 前缀。
5. `npm run dev`，访问 `/paper` 登录。生产部署应使用 HTTPS。

登录 Cookie 为 HttpOnly、SameSite=Strict，有效期 12 小时；HTTPS 请求设置 Secure。所有实验读写接口均验证会话，写入额外检查 Origin。服务端 Cron 通过独立 Bearer 密钥授权。退出会清除当前浏览器 Cookie；如需使已复制或其他设备的会话失效，轮换会话签名密钥。进程内登录限速仅作为辅助，公开部署可在网关增加持久限速。

## 数据库迁移：先辨别现有状态

### 新 PostgreSQL 空库

```text
npx prisma migrate deploy
```

依次执行 PostgreSQL 新闻基线与实验功能迁移。旧的 SQLite SQL 归档在 `prisma/legacy-sqlite-migrations/`，不再混入 PostgreSQL 的迁移链；没有删除原始 SQL 内容。

### 已通过 db push 建立的 PostgreSQL

先备份，并在恢复出的独立副本演练。核对当前数据库是否与 `prisma/postgresql-baseline.prisma` 完全一致；可用 Prisma 的只读 diff 检查。以 PowerShell 为例：

```powershell
npx prisma migrate diff --from-url "$env:DIRECT_URL" --to-schema-datamodel prisma/postgresql-baseline.prisma --exit-code
```

退出码 0 表示无差异；2 表示存在结构差异。这个命令不执行 SQL。存在差异或已有不同迁移历史时应停止，先核实原因，不能盲目标记已迁移。确认基线、备份和副本演练都通过后，才在目标环境运行：

```text
npx prisma migrate resolve --applied 20260429000000_postgresql_baseline
npx prisma migrate deploy
```

新增迁移保留原有新闻，并把旧分析标记为 `legacy`，因为其模型和 Prompt 版本无法可靠补齐。若已有 SQLite 数据，需另做数据迁移；不能把 SQLite 连接串直接交给 PostgreSQL schema。

## 第一次建立实验

1. 导入开始日及后续日期的交易日历，包含休市日。
2. 导入开始日沪深 300 价格指数 `000300` 的核实收盘点位。
3. 创建账户：设置初始资金、开始日、统一模拟费率和最低费用，选择 1–10 个自选标的。
4. 初始状态全部为现金，开始日净值为 1。账户初始设置锁定，暂不提供重置、追加或提取资金接口。

第一版仅支持 `60xxxx.SH` / `00xxxx.SZ` 格式的沪深主板普通 A 股。白名单不校验证券实际上市状态，操作者必须核对代码、证券类别和日历来源；不支持科创板、创业板、北交所、B 股、ETF、美股、衍生品、融资融券和做空。

费用预填值仅是实验示例，不是对实际税费的声明。统一模拟费率不能完整还原佣金、税费和滑点。成交假设也不保证现实市场可获得该价格。

## 每个交易日

1. 收盘后导入当天沪深 300 和相关标的行情；暂停交易的持仓也需有明确来源的估值价格。
2. 点击结算。程序从上次已检查日期继续，处理前一交易日决策产生的指令，并生成每日估值。
3. 核对持仓、现金和未成交原因。
4. 15:00 后记录当天决策及理由，可选择调整持仓、继续持有或空仓等待，并引用当时系统可见的新闻。
5. 保存后锁定实际提交时间、当时账户状态与新闻/分析副本；下一交易日按约定规则执行。未记录决策的交易日明确标记未记录。

不能回填历史决策，客户端提供的决策日期会被拒绝。当天账户尚未结算时不能锁定决策。每账户每天一份决策，同内容重复提交复用原记录，不同内容不能覆盖。每份决策内每标的最多一条指令。

先卖后买；买入数量须为 100 股整数倍，卖出数量须为 100 股整数倍或一次卖清全部零股。现金/持仓不足时整笔不成交，不部分成交。停牌、涨停或跌停均采用保守的不成交规则。缺行情时整个交易日暂停，避免同日只成交一部分而生成不完整净值。T+1 通过“收盘后决策、下一交易日执行”及每标的每天一条指令约束实现。

新闻发布时间、系统抓取时间和分析完成时间各自保留。没有成功分析时不会生成中性占位成功记录。AI 分析是参考证据，不能保证其判断准确，也不自动映射成 A 股指令。

## CSV 格式

`public/paper-templates/` 提供表头模板，里面的占位内容必须替换。模板不包含可用于实验的真实行情。支持 UTF-8、BOM、CRLF 和标准引号转义。单次最多 1 MB、2,000 行，重复键、错误表头、无效日期、非正价格会整批拒绝。

| 类型     | 精确表头                          | 规则                                                                              |
| -------- | --------------------------------- | --------------------------------------------------------------------------------- |
| 交易日历 | `date,is_open,source`             | 日期为 YYYY-MM-DD；开市 1，休市 0；所有中间日期都需覆盖。已导入的开休市状态锁定。 |
| 收盘行情 | `date,symbol,close,status,source` | `000300` 为基准，股票代码带 .SH/.SZ；最多四位小数；来源必填。                     |

行情状态为 `OPEN`、`HALTED`、`LIMIT_UP`、`LIMIT_DOWN`。基准只能为 OPEN。不能导入未来或当天尚未收盘的报价，也不能给未确认为开市的日期导入报价。

股票使用**未复权价格**，并通过公司行为流水记录实际应得的净现金分红或新增股数；不能把前复权股价直接乘以原股数当作真实资产。持仓的停牌估值会明确标记，不推测缺失行情。基准使用价格指数，不包含股息再投资；账户收到分红时存在比较口径差异，未来可以扩展全收益基准。

完全相同的行情重复导入不新增记录。相同日期和代码的价格、状态或来源修正会新增行情版本，并重新计算已经结算的估值；历史估值版本保留，已模拟成交的价格和费用不改写。交易日历矛盾必须先人工核对，不能通过普通导入改写。

## 公司行为与数据更正

分红或送转事件由操作者核对本账户权益后手工确认，保存来源、说明及实际录入时间。只支持正向的现金分红和新增股数，不支持负数、出入金、撤销、逆向拆股、退市赔付等复杂事项。不得用虚构分红来追加资金或掩盖错误。

如果发生不支持的公司行为，或不可撤销事件录入错误，应停止解释该实验的后续绩效，先在备份副本中核对修复路径。第一版不提供删除/覆盖账本历史的按钮。不能验证的数据不能当作有效业绩对外使用。

## 计算口径

```text
资产 = 现金 + 持仓数量 × 未复权收盘价之和
累计收益 = 资产 / 初始资金 - 1
基准累计收益 = 当日沪深300点位 / 开始日点位 - 1
超额收益（百分点）= 两项累计收益之差 × 100
最大回撤 = 各日 (1 - 当日资产 / 此前最高资产) 的最大值
```

最大回撤包含开始日初始资金高点；行情与基准使用同一组交易日。交易金额以整数分计算，四位小数报价乘股数后四舍五入到分，手续费再独立四舍五入到分。收益比率只在展示时转换为浮点数。

## 备份与恢复

页面导出的 JSON 包含全部账户记录、决策证据与账户上下文、指令、成交、公司行为、日历、行情修订和估值版本。下载文件含实验记录，应妥善保管。

JSON 用于审计与核对，第一版不提供不受校验的直接覆盖导入。生产恢复应使用 PostgreSQL 的数据库备份（例如受控环境中的 pg_dump/pg_restore），先恢复到独立数据库核对，再切换连接。不要在运行中的账户上随意执行 reset 或 db push。

## 自动任务

`vercel.json` 的新闻抓取计划为每天 UTC 00:00（北京时间 08:00）；实验结算计划为 UTC 08:30（北京时间 16:30）。Cron GET 和页面人工 POST 均已区分授权。手工 CSV 尚未准备好时，结算返回待补数据原因，不声称已完成。

需要检查 Vercel 套餐的调度精度、函数时长、Cron 日志和数据库连接数。单次结算最多检查 90 个日历日，大区间需再次触发。AI 每次自动管道最多处理 50 条，剩余待分析记录留待下一次；命令行 `npm run reanalyze:all` 可显式遍历全部记录。

## 验证

```text
npm run test
npm run typecheck
npm run lint
npm run test:integration
npm run build
npm run test:http
```

集成测试自动创建只绑定本机回环地址的临时 PostgreSQL，不读取生产数据库连接，随机凭据仅在进程中使用。测试覆盖空库迁移、旧 PostgreSQL 基线升级保留新闻、证据不可变、跨休市日执行、并发幂等、缺价阻断、修订重估值、分红、资金与回撤、登录/Origin 校验、导出及分析禁用状态。测试结束关闭临时数据库。

`npm run preview:paper` 使用独立的合成演示库，仅供本地体验与页面检查；终端会显示一次临时登录口令。关闭后演示数据不保留。真实实验请配置自己的持久数据库。
